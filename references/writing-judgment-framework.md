# 学术写作判断方法库

这份参考不是范文摘抄，也不是句式库。它把用户提供的课程讲义、范文、批注前后版本和逻辑分析案例中的“修改动作”还原为可迁移的判断方法。使用它的目标是先理解一段文字为什么需要改，再决定改成什么样。

## 1. 总体判断框架

任何改写先回答五个问题：

1. 这段文字在全文、章节和段落中分别承担什么功能？
2. 它要把读者从哪里带到哪里？上一段交给它什么，下一段需要它交出什么？
3. 当前问题属于事实、证据、研究逻辑、结构、表达还是格式层？
4. 现有材料足以支持多强的主张？哪些内容只是意图、假设、待核验事项或建议？
5. 改动后是否更短、更清楚、更有推进力，同时保留作者真正想表达的判断？

修改理由必须能落到上述问题之一。不能只说“更顺”“更学术”“更高级”。

### 六层问题诊断

按以下顺序诊断，不能用下层润色掩盖上层缺陷：

1. **事实层**：时间过旧、数字无来源、引用对象不对应、术语或变量前后不一致。
2. **证据层**：主张没有数据/文献/推导支撑，结果与表格不一致，启示超出研究设计。
3. **问题层**：研究对象、核心问题、研究边界和要解决的困难没有说清楚。
4. **结构层**：章节功能错位，段落混合多个任务，目标、内容、方法、结果和贡献没有对应。
5. **论证层**：背景没有导出问题，文献没有导出缺口，方法没有回答问题，结果没有回扣贡献。
6. **表达层**：冗长、重复、语病、机械连接、中文式英文、过度防御或无效强调。

如果问题停在前五层，先输出诊断和结构修改，不直接逐句润色。

## 2. Keyline：让文章向前推进

Keyline 不是漂亮的中心句，而是段落的逻辑锚点。每个段落先写一句内部关键句，说明本段要完成的动作：引出背景、界定对象、概括文献、指出不足、提出问题、说明方法、报告结果、解释机制、提出贡献或给出启示。

检查关键句的三种关系：

- **回收**：它承接上一段已经建立的对象或判断；
- **推进**：它增加一个新的问题、比较、证据或解释；
- **交接**：它为下一段准备明确入口。

如果一段同时承担背景、文献综述、研究问题和方法介绍，应拆开或重排。增加“此外”“因此”“综上所述”不能替代逻辑交接。

## 3. 摘要的判断与重写

摘要是全文的压缩模型，不是引言的前言，也不是意义宣传。默认顺序是：

1. 研究对象和现实/学术问题；
2. 本文要回答的具体问题或目的；
3. 数据、材料、方法和研究范围；
4. 最主要的结果，按问题顺序写；
5. 理论贡献、实践启示或方法价值。

每句话都要服务这五项之一。删除“某领域很重要”“扮演重要角色”等不能引出本文问题的套话。摘要中的研究发现只能来自已给出的结果；没有结果时写研究目标或预期，不把预期写成发现。摘要要短，但不能牺牲研究对象、方法和主要发现的可识别性。

## 4. 引言的判断与重写

引言不是背景资料堆积，核心任务是让读者自然接受“为什么必须研究这个问题，以及本文怎样回答”。通常按以下链条组织：

1. 宏观背景或现实变化：只保留能把读者带向研究问题的 1–2 个事实；过时或无关的统计资料删除或换成当前可核验来源。
2. 具体现象/对象：说明研究对象正在面对的实际困难，不泛泛谈整个行业。
3. 相关研究：按观点、机制、对象、方法或适用条件归类，选代表性文献，不逐篇报流水账。
4. 研究不足：指出已有研究在哪个对象、条件、目标或方法上不能充分回答当前问题。
5. 本文问题：用“检验什么、解释什么、比较什么、设计什么”写出可回答的问题。
6. 研究思路和材料：说明本文用什么数据/模型回答问题，不提前展开全部技术路线。
7. 结果与贡献预告：只写已经得到且能核验的核心结果，再说明贡献落在哪个问题上。

宏观政策或国家战略只有在帮助界定研究必要性时才保留，控制篇幅，不能用口号替代问题意识。研究目的句是概括性的，后文再展开研究内容、方法和价值；目的句不要塞入全部步骤。

## 5. 文献综述的判断与重写

“综”是综合、分类和压缩，“述”是比较、评议和指出边界，不是把每篇文章都复述一遍。执行时建立以下矩阵：

| 维度 | 要问的问题 |
|---|---|
| 对象 | 研究了谁、什么场景、什么层级？ |
| 问题 | 解决了什么具体问题？ |
| 视角/机制 | 用什么理论、机制或解释路径？ |
| 方法 | 用什么数据、模型、算法或实验？ |
| 范围 | 在什么条件下成立，省略了什么？ |
| 结果 | 得到什么可核验结论？ |
| 缺口 | 哪个限制能转化成本文的研究任务？ |

优先按“问题—视角/机制—方法—适用条件”分组，每组末尾给出小结和与本文的关系。文献很多时选择与当前问题最紧密、最有代表性或最可能被评审关注的文献；其余文献不必全部写入正文。不能用“研究较少”“国内空白”“意义重大”单独制造缺口。

## 6. 开题报告的层级判断

开题报告中的几个概念不能混写：

- **总体目标**：本项目最终要回答的核心问题；
- **研究内容**：为回答问题要完成的 2–5 个工作包，每项应说明研究对象、模型/方法、实验或分析和预期可观察结果；
- **关键科学/技术问题**：只有通过研究才能解决的困难、机制或权衡，不是“收集数据”“完成某阶段”这类任务名；
- **技术路线**：工作包之间的顺序、依赖、输入输出和方法连接，最好用总框架图再逐项展开；
- **研究方法**：为什么该方法适合这个问题，以及它的假设和边界；
- **预期成果**：可检查的论文、模型、算法、数据、系统、规律或决策建议；
- **可行性与风险**：数据、权限、方法、时间、算力、评价指标和替代路径。

研究内容应使用“建立什么模型/采用什么方法/开展什么实验/分析什么影响/得到什么结果”的语气。把技术路线改写成“研究内容”，或把基础阶段改写成“关键科学问题”，都会造成层级错位。

创新要拆成两类：问题/视角创新，以及针对问题特征的模型、算法或实验设计创新。每项创新都要能回指研究缺口和可观察证据，不能只写“首次”“系统”“综合”。

## 7. 研究型论文的结构判断

模型、算法和实证论文要形成可追溯链：

`问题与困难 → 相关研究及不足 → 研究问题/假设 → 模型或设计 → 方法/实现 → 数据与实验 → 结果比较 → 机制或含义 → 贡献与边界`。

方法章节不能只介绍工具。每个组件都要说明承担的子任务、输入、输出、与前后组件的依赖，以及由哪个实验或消融检验。把多个模块称为“协同”“有效”“鲁棒”“显著提升”时，必须有基线、消融、敏感性或复现结果支撑。

结果段落按“问题—设置—比较—结果—解释—边界”组织。图表只展示数据实际支持的关系，不能从趋势图直接补出因果、机制或应用效果。结论回收主要发现和贡献；限制说明影响主张的真实边界；未来工作不能代替当前研究没有完成的证据。

## 8. 结论与管理/实践启示

结论至少完成三件事：简明回收研究做了什么，按研究问题给出主要结论和贡献，在证据允许范围内说明启示、边界和未来方向。实践启示必须由研究结论推出可行动对象和动作；不能添加研究没有测量的宏大建议。与研究结论无关、无法执行或只是价值判断的启示应删除或合并。

## 9. 批注与修订痕迹的学习方式

遇到带批注、修订或前后版本的材料，先建立“原文—改后—批注意图—可迁移规则”四列表，而不是只记住改后句子：

| 原文问题 | 改后动作 | 批注真正解决的问题 | 可迁移规则 |
|---|---|---|---|
| 背景过长、数据过时 | 删除/压缩，保留与问题直接相关的事实 | 让背景服务问题，不让旧资料占据篇幅 | 先检查时效性和功能，再决定是否保留 |
| 研究工作和研究目的混在一起 | 把概括句与工作细节分开 | 让读者先知道目的，再理解方法 | PURPOSE 句先概括，步骤后展开 |
| 文献逐篇排列 | 按观点或问题归类 | 让综述形成评述和缺口 | 以面概括、以点支撑 |
| 技术路线写成研究目标 | 删除或移到总体路线 | 恢复开题层级 | 目标回答“研究什么”，路线回答“怎么推进” |
| 基础阶段写成关键问题 | 改成真正的机制、权衡或难点 | 防止把任务清单冒充科学问题 | 关键问题必须只能通过研究解决 |
| 结论/启示冗长、泛化 | 按发现压缩并绑定行动 | 让启示成为研究结论的管理转译 | 每条启示都要有结论来源和行动对象 |
| 方法论文把组件并列介绍 | 写出组件依赖和证据 | 让算法成为解决问题的链条 | 每个组件都要有任务、输入、输出和检验证据 |

批注中的“精炼”“往前提”“不言自明”“需要给出依据”等词不能机械执行。先判断它针对的是功能、篇幅、证据、结构还是表达，再实施相应动作。

## 10. 中英文写作与润色

### 中文学术写作

- 句子围绕一个判断展开，主语、对象、关系和证据明确；
- 研究问题、方法、结果和贡献直接说，不用大量套话铺垫；
- 允许作者对结果作有力度的解释，但不把相关关系写成未经设计支持的因果；
- 删除重复的“有助于、具有重要意义、进一步推动”等空泛表达，除非后面紧跟具体对象和机制；
- 中文论文优先保证层次、节奏和信息密度，不追求每句都对称。

### 英文学术写作

- 先确定段落功能和 topic sentence，再处理句法和词汇；
- 不逐字翻译中文的“随着、从而、综上所述”，根据真实逻辑选择 cause, contrast, extension, evidence 或 implication；
- 保持 subject–verb clarity，避免一个句子塞入背景、方法、结果和贡献；
- 用具体动词表达研究动作和结果，区分 examine, estimate, identify, suggest, demonstrate 等证据强度；
- 贡献段突出本文新增了什么，限制段只放真正影响解释的限制，不把整篇英文写成免责声明。

### 润色等级

每次润色先标明等级：

1. **意义不变的语言润色**：语法、词汇、衔接和自然度，不能改变数字、引用、结论或主张强度；
2. **逻辑重构**：允许删、移、并、补过渡和重写关键句，但必须解释结构变化；
3. **论证增强**：只有在用户授权且证据足够时，才能增强贡献、机制或实践含义；任何意义变化都要显式标出。

默认不是压缩。保留原文中承担解释、限定、比较、方法关系或结果边界的有效信息；只删除真正重复、偏题或破坏推进的内容。若为了重排逻辑而删去、合并或弱化信息，必须给出删改清单，并说明该信息为何不再需要或应移到其他位置。需要短摘要时另行标注为“压缩版”，不能把压缩版冒充普通润色稿。

英文润色和中文润色都要同时交付：修改稿、修改理由、保留的事实/数字/引用、仍需作者判断的问题。不要只给一版“看起来更像母语”的文本。

## 11. 标准执行流程

1. 先读全文或至少读完整章节，确认研究对象、目标读者、交付物和不能改变的事实。
2. 画全文主线，标注章节功能和每段 Keyline。
3. 建立“主张—证据—位置—责任边界”表，标出待补项。
4. 按影响从高到低处理：事实/证据 → 问题/结构 → 论证 → 段落 → 句子 → 格式。
5. 每个删除、移动、合并或新增都写明解决的具体问题；没有理由的改动不执行。
6. 先给结构版或诊断版，再给完整润色稿；如果用户只要润色，也要先在内部完成结构检查。
7. 对中英文稿分别做语言自然度复核，但不让语言优化改变科学含义。
8. 最后做反向审查：读者能否说出本文回答什么、凭什么回答、得到什么、贡献是什么、哪些地方不能外推。

## 12. 禁止的伪学习

- 不复制课程案例的题目、数据、变量、结论、期刊和句式；
- 不把老师对某篇文章的修改偏好当作所有学科的硬格式；
- 不把“精炼”理解为删除必要方法、结果或证据；
- 不为追求像人而夸大结果、隐藏负面发现或补造引用；
- 不把批注中的待补项、问号或占位符当成已经核实的事实；
- 不把一篇范文的结构当成每篇论文唯一结构。
