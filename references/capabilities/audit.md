# 开题逻辑、可行性与边界审查

## 审查顺序

1. 检查核心问题是否明确，题目、目标、内容和结论是否围绕同一问题。
2. 检查文献缺口是否有证据，创新主张是否超过已有材料支持的强度。
3. 检查目标—内容—方法—路线—评价—成果是否逐项对应。
4. 检查数据、样本、权限、时间、预算、伦理和技术条件是否足以支撑计划。
5. 检查假设、适用边界、风险、替代方案和失败判据。

## 常见断裂

- 从工具或算法出发，反向拼接研究问题。
- 研究目标很大，但研究内容和评价指标很小或没有定义。
- 用“预期开发系统”代替理论贡献、方法贡献或可验证结果。
- 把预测结果、应用价值或创新性写成已经证实的事实。
- 只写成功路线，不写数据不足、迁移失败、指标失效或资源受限时怎么办。

## 输出格式

- 阻断问题：必须先修复
- 重要问题：影响可信度或可行性
- 一般问题：可在扩写或润色阶段处理
- 证据缺口：需要补充的文献、数据或来源
- 回退位置：应回到问题、缺口、方法还是评价层重写

## 判停

核心问题、关键数据、方法依据或评价标准缺失时，输出计划草案与待确认清单，不把草案包装成定稿，也不替用户补造事实。
